# CI/CD · K8s 배포 구현 플랜

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** n3nai(Vite SPA)를 `node:20-alpine + serve -s dist` 컨테이너로 GHCR에 푸시하고, `draft1` push → d2 클러스터, `main` push → prod 클러스터로 자동 배포하는 CI/CD를 구축한다.

**Architecture:** 사내 표준(jikji_homepage_static 패턴)을 그대로 따라 GHCR(`ghcr.io/n3n-dev/n3nai`) + Traefik Ingress + raw YAML 매니페스트(`k8s/d2/combined.yaml`, `k8s/prod/combined.yaml`) + 단일 `deploy.yml` + self-hosted runner 구조. 배포는 `apply → set image → rollout status` 시퀀스, 실패 시 `kubectl rollout undo` + `exit 1`.

**Tech Stack:** Vite 8 + React 19 + TypeScript, Node 20 alpine, `serve@^14`, Docker Buildx, GitHub Actions, kubectl, Traefik Ingress, Rancher kubeconfig.

**Spec:** `docs/superpowers/specs/2026-05-26-cicd-k8s-design.md`

## 파일 구조

| 경로                           | 동작              | 책임                                                                                        |
| ------------------------------ | ----------------- | ------------------------------------------------------------------------------------------- |
| `package.json`                 | 수정              | `serve` 의존성 + `start` 스크립트 추가                                                      |
| `Dockerfile`                   | 신규              | Multi-stage 빌드: node 빌더 → node 런타임(`serve -s dist`)                                  |
| `.gitignore`                   | 수정              | `dist/` 추가                                                                                |
| `dist/`                        | 삭제(트래킹 해제) | `git rm -r --cached dist/`로 트래킹만 해제                                                  |
| `k8s/d2/combined.yaml`         | 신규              | d2 클러스터용 Deployment + Service + Ingress (replicas 1, host `n3n-ai-dev.d2.nthreen.com`) |
| `k8s/prod/combined.yaml`       | 신규              | prod 클러스터용 Deployment + Service + Ingress (replicas 2, hosts `n3n.ai`/`www.n3n.ai`)    |
| `.github/workflows/deploy.yml` | 덮어쓰기          | 기존 GitHub Pages용 워크플로우를 새 build-and-push + deploy 워크플로우로 교체               |

각 파일은 하나의 책임만 갖고, 변경이 같이 발생하는 단위(매니페스트 d2/prod)만 디렉토리로 묶었다. 매니페스트를 Kustomize·Helm으로 추상화하지 않은 이유는 사내 표준의 외형(raw YAML 단일 파일)을 유지하기 위함이다.

- [ ] **Step 7.2: 새 워크플로우 작성 (전체 덮어쓰기)**

`/Users/user/projects/n3nai/.github/workflows/deploy.yml`을 다음 내용으로 완전 교체:

```yaml
name: Build and Deploy to K8s

on:
  push:
    branches: [draft1, main]

env:
  IMAGE_NAME: ghcr.io/n3n-dev/n3nai
  NAMESPACE: homepage-n3n-ai
  APP_NAME: n3nai

jobs:
  build-and-push:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
    steps:
      - uses: actions/checkout@v4

      - name: Log in to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3

      - name: Build and push
        uses: docker/build-push-action@v5
        with:
          context: .
          push: true
          platforms: linux/amd64
          tags: |
            ${{ env.IMAGE_NAME }}:latest
            ${{ env.IMAGE_NAME }}:sha-${{ github.sha }}

  deploy:
    needs: build-and-push
    runs-on: self-hosted
    steps:
      - uses: actions/checkout@v4

      - name: Install kubectl
        uses: azure/setup-kubectl@v3
        with:
          version: "v1.28.0"

      - name: Resolve target env
        id: target
        run: |
          if [ "${{ github.ref }}" = "refs/heads/draft1" ]; then
            echo "env=d2" >> "$GITHUB_OUTPUT"
          elif [ "${{ github.ref }}" = "refs/heads/main" ]; then
            echo "env=prod" >> "$GITHUB_OUTPUT"
          fi

      - name: Write kubeconfig (d2)
        if: steps.target.outputs.env == 'd2'
        run: |
          mkdir -p "$RUNNER_TEMP/.kube"
          echo "${{ secrets.KUBECONFIG_D2 }}" > "$RUNNER_TEMP/.kube/config"
          chmod 600 "$RUNNER_TEMP/.kube/config"

      - name: Write kubeconfig (prod)
        if: steps.target.outputs.env == 'prod'
        run: |
          mkdir -p "$RUNNER_TEMP/.kube"
          echo "${{ secrets.KUBECONFIG_PROD }}" > "$RUNNER_TEMP/.kube/config"
          chmod 600 "$RUNNER_TEMP/.kube/config"

      - name: Deploy
        env:
          KUBECONFIG: ${{ runner.temp }}/.kube/config
        run: |
          kubectl -n $NAMESPACE apply -f k8s/${{ steps.target.outputs.env }}/combined.yaml
          kubectl -n $NAMESPACE set image \
            deployment/$APP_NAME \
            $APP_NAME=$IMAGE_NAME:sha-${{ github.sha }}
          kubectl -n $NAMESPACE rollout status \
            deployment/$APP_NAME --timeout=120s

      - name: Rollback on failure
        if: failure()
        env:
          KUBECONFIG: ${{ runner.temp }}/.kube/config
        run: |
          kubectl -n $NAMESPACE rollout undo deployment/$APP_NAME || true
          exit 1
```
